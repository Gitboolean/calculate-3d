| 18 | 2 | `get_connection` uses a yield dependency with the default `scope="request"` (FastAPI 0.162), so the commit runs **after** the response is sent. If the commit fails, the client still gets `200` and the write is lost. It also creates a read-after-write race for the UI. The R11 tests can't see this because they read the DB after the `with TestClient` block exits. Probe (re-run by the orchestrator): a deferred FK violation with plain `Depends(get_connection)` returns `200 {"saved":"yes"}` and stores 0 rows. With `scope="function"` it returns `500` problem+json and stores 0 rows. Every future write module copies this template | `backend/src/calculate3d/core/db.py:31-34`, `backend/tests/integration/test_get_connection.py:18,22` | `CLAUDE.md` ("one transaction per request"; "every error renders problem+json"), R11 | **Fix now** → R14 |
