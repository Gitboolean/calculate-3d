# 0003 — Recompute catalog prices on every read in one batched pass, never cache them

- **Status:** Accepted
- **Date:** 2026-10-28
- **Deciders:** Anton Pohorielov (автор), architecture-design pass

## Context

Каталог зберігає лише параметри виробу (витрату пластиків і час друку), а не готову ціну. Це інваріант із CONTEXT («Мінімальний донат завжди розраховується з поточних налаштувань цін») і головний ризик брифу: виріб, непомітно проданий за старою ціною. AC-13 вимагає, щоб після зміни ціни пластику каталог одразу показував новий мінімальний донат без жодних дій з виробом. Відкриття каталогу має вкладатися в p95 ≤ 500 мс на 1 000 виробах і 50 пластиках.

## Decision drivers

- Інваріант CONTEXT + конвенція `CLAUDE.md` «Catalog stores parameters, never a final price».
- QG-1 Точність: каталог показує ту саму суму, що й розрахунок (ADR 0002).
- QG-2: відкриття каталогу p95 ≤ 500 мс (1 000 виробів, 50 пластиків) — PRD §6.

## Considered options

1. **Перерахунок при кожному читанні, пакетно** — фіксована кількість SQL-запитів (вироби, рядки пластиків усіх виробів, налаштування цін і ціни пластиків), далі розрахунок у пам'яті тією самою функцією, що й розрахунок.
2. **Кеш цін з інвалідацією при зміні налаштувань** — швидкість читання майже стала, але кожна зміна цін мусить скидати кеш; пропущена інвалідація відтворює саме той ризик, від якого захищає інваріант.

**Розглянуто й виключено обмеженням** (не рівноцінна альтернатива):

- *Розрахунок у SQL (JOIN + SUM)* — SQLite рахує дроби в `REAL`, а `CLAUDE.md` забороняє float для грошей і бізнес-логіку в БД («DB is dumb storage», проєктний ADR 0002).

## Decision outcome

**Chosen:** Option 1. Сервіс каталогу завантажує дані пакетно (без N+1 — без окремого запиту на кожен виріб) і для кожного виробу викликає ту саму функцію розрахунку, що й ендпоінт розрахунку (межі модулів — SAD §5). Ціна існує лише у відповіді API і ніде не зберігається. Фільтр за частиною назви й абетковий порядок (AC-12) застосовуються в тому самому проході.

## Consequences

**Positive**
- Застаріла ціна неможлива за побудовою: її ніде не збережено.
- Немає коду інвалідації, тож немає й класу багів «забули скинути кеш».
- AC-13 виконується без спеціальної логіки.

**Negative**
- Час відповіді росте лінійно з розміром каталогу; на десятках тисяч виробів знадобиться пагінація (див. §7 пороги, §11).
- Кожне відкриття каталогу перераховує всі вироби, навіть ті, що не потрапили на екран.

**Neutral**
- Якщо колись знадобиться кеш, його можна додати за тим самим інтерфейсом сервісу каталогу, не змінюючи API.
