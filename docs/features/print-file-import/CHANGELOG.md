# Changelog — print-file-import

## print-file-import — витрата пластиків і час друку з нарізаного файлу Bambu Studio замість ручного переписування

**What:** у розрахунку і на сторінці виробу з'явилася кнопка «Імпортувати файл слайсера». Автор
обирає нарізаний файл проєкту Bambu Studio (`.3mf`), і інструмент сам заповнює витрату кожного
пластику та час друку. Відповідно до цих даних одразу показується мінімальний донат. Час
округлюється вгору до хвилини, а грами — вгору до 0,01 г (після того, як сумуються філаменти,
що відповідають тому самому пластику), тому імпортований донат ніколи не менший за точний.
Філамент слайсера (назва пресету + колір) один раз зіставляється з пластиком із налаштувань
цін. Зіставлення запам'ятовується, коли виріб зберігається, і далі підставляється саме.
Ціну інструмент завжди бере з поточних налаштувань. У наявному виробі імпорт спершу показує
«було → стало» і змінює виріб лише після підтвердження: або цілком, або ніяк. Ненарізаний
файл, файл не з Bambu Studio, пошкоджений файл, файл із кількома нарізаними пластинами, файл
понад 100 МБ або файл із числами поза межами відхиляються з поясненням простими словами і
пропозицією ввести дані вручну. Нулі мовчки не підставляються. Сам файл не зберігається:
сервер читає лише чотири службові частини архіву в пам'яті й одразу його відкидає.

**Why:** автор переписував грами кожного пластику й час друку зі слайсера вручну. У
багатоколірному друці таких чисел кілька, і промивку легко пропустити або помилитися на
цифру. Така помилка дає правдоподібний, але хибний мінімальний донат ([PRD](./PRD.md) §1–§2).
Ключові рішення:

- [ADR-0001](./adr/0001-parse-slicer-file-on-server-and-keep-only-numbers.md): файл розбирає
  сервер, а з нього беруться лише числа. Файл ніде не зберігається.
- [ADR-0002](./adr/0002-upload-slicer-file-as-raw-octet-stream-body-held-in-memory.md): файл
  надходить сирим тілом `application/octet-stream` (≤ 100 МБ) і тримається в пам'яті. Гард
  ADR 0007 етапу 1 пропускає `octet-stream` лише на `POST /api/importing/parse`.
- [ADR-0003](./adr/0003-remember-filament-mappings-in-the-item-save-transaction.md):
  зіставлення пластиків записуються в тій самій транзакції, що й виріб. Тому подивитися ціну,
  нічого не зберігши, означає нічого не запам'ятати.
- [ADR-0004](./adr/0004-compose-quote-rows-in-the-web-from-exact-milligrams.md): API віддає
  точні `usage_mg`. Веб сумує філаменти одного пластику й лише потім округлює суму до `_cg`
  (AC-03: 2,001 + 2,001 → 4,01 г).
- [ADR-0005](./adr/0005-add-an-importing-module-that-owns-the-parser-and-filament-mappings.md):
  новий модуль `importing` відповідає за парсер і таблицю `filament_mappings`. `catalog`
  звертається до нього лише через `service.py`.

Архів читається в межах бюджету пам'яті (SAD §7–§8): не більше 10 000 записів і 4 000 000 байт у
центральному каталозі, не більше 8 000 000 байт розпакованого розміру на кожну службову
частину. G-code ніколи не розпаковується.

**How to use:** `make run` → <http://127.0.0.1:8000>. На сторінці «Розрахунок» або на сторінці
виробу натисніть «Імпортувати файл слайсера», для кожного нового філаменту оберіть пластик і
збережіть (на сторінці виробу — підтвердіть «було → стало»). API описано в
[openapi.yaml](./contracts/openapi.yaml):

```http
POST /api/importing/parse
Content-Type: application/octet-stream
<байти vtulka_A.gcode.3mf>
→ 200 {"plate":{"index":1,"name":""},"print_time_s":5880,
       "filaments":[{"filament_name":"Bambu PLA Basic @BBL A1M","filament_type":"PLA",
                     "filament_color":"#FFFFFF","usage_mg":11540,"plastic_id":null}]}
```

Зіставлення надсилаються разом із виробом: це необов'язкове поле `filament_mappings`
(`[{filament_name, filament_color, plastic_id}]`) у `POST`/`PUT /api/catalog/items`. Нові коди
помилок (RFC 9457 `application/problem+json`): `importing.settings_missing` (409),
`importing.not_slicer_project`, `importing.not_sliced`, `importing.multiple_sliced_plates`,
`importing.corrupted_file`, `importing.no_filament_usage`, `importing.print_time_out_of_range`,
`importing.plastic_not_found` (422), `importing.file_too_large` (413).

**Operational notes:**

- Migration: одна нова Alembic-ревізія `20261110_2110_create_filament_mappings` (`f6268165ee91`
  поверх `65f15a51514f`). Вона перенесена зі staged [`migrations/`](./migrations/) і створює таблицю
  `filament_mappings`: унікальна пара (назва, колір), FK на `plastics` з `ON DELETE CASCADE`.
  Тому видалення пластику прибирає й зіставлення (AC-11). `make run` запускає `make migrate`
  сам. Цикл upgrade → downgrade → upgrade перевірено тестом і вручну на окремій БД.
- Feature flag / config: немає. Нових змінних середовища немає, сервер, як і раніше, слухає
  лише `127.0.0.1`.
- Memory: один імпорт тримає в пам'яті тіло до 100 МБ (≈ 132 МБ піку за SAD §7). Процес
  однокористувацький, тож це ок, але на машині з малою пам'яттю варто про це знати.
- Rollback: зупиніть сервер і виконайте `make migrate-down` один раз. Буде видалено
  `filament_mappings` разом із запам'ятаними зіставленнями, а вироби, пластики й налаштування
  не зачіпаються. Потім зробіть revert мерджу. Перед відкатом варто скопіювати
  `backend/var/calculate3d.db`.

**Acceptance criteria delivered:** AC-01 … AC-15 з AC-09b, усього 16 AC ([PRD](./PRD.md) §5).
Сюди входять: імпорт однокольорового й багатокольорового еталона з донатом до копійки
(AC-01–02), округлення лише вгору (AC-03), блокування без налаштувань цін (AC-04),
«було → стало» з підтвердженням або скасуванням без часткових змін (AC-05–06), зіставлення
філаментів (запам'ятовування, заміна, жодних мовчазних нулів, відсутній пластик, питання перед
сумуванням, поточна ціна та видалення пластику — AC-07–11), відхилення поганих файлів за чітким
порядком перевірок (AC-12–14) і захист від сторонніх сайтів та інших пристроїв (AC-15).
