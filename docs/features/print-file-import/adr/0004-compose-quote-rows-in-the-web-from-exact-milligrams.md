# 0004 — Compose quote rows in the web from exact milligrams

- **Status:** Accepted
- **Date:** 2026-11-09
- **Deciders:** Anton Pohorielov (автор), architecture-design pass

## Context

Після розбору (ADR 0001) в автора на екрані є список філаментів слайсера і вибір пластику для кожного. Розрахунок (`costing` `QuoteInput`) приймає рядки `{plastic_id, usage_cg}` без повтору пластику. AC-03 і AC-10 вимагають, щоб філаменти одного пластику сумувалися **з точних** витрат і лише сума округлювалася вгору до 0,01 г (2,001 г + 2,001 г → 4,01 г). Вибір пластику й підтвердження сумування (AC-10) відбуваються в браузері, а сервер файл уже відкинув. Питання — хто складає рядки: веб чи окремий серверний крок.

## Decision drivers

- QG-1 Точність імпорту: округлення лише вгору, 0 тихих хибних імпортів (CONTEXT «тихий хибний імпорт»).
- cost-calculator ADR 0004: кількості — масштабовані цілі числа з одиницею в назві, без `float`.
- cost-calculator ADR 0002: ціну, розбивку й межі рахує лише сервер.
- §2: бюджет E = 2 тижні.

## Considered options

1. **Веб із точних міліграмів** — сервер повертає витрату кожного філамента цілим `usage_mg`; чиста TS-функція групує за пластиком, додає мг і округлює суму вгору до `usage_cg`.
2. **Серверний крок «скласти»** — другий ендпоінт модуля імпорту приймає філаменти з відповіді розбору разом із вибором пластиків і повертає готові рядки (точна сума через `Fraction`).

## Decision outcome

**Chosen:** Option 1.

- Розбір віддає `usage_mg` — точну витрату в міліграмах. Bambu Studio пише грами з двома знаками (`used_g="15.49"`), тож перетворення точне. Число з більш ніж трьома знаками округлюється вгору до мг; вниз — ніколи.
- `features/slicer-import/model/compose.ts` — чиста функція: групує філаменти за обраним `plastic_id`, додає цілі мг і повертає `usage_cg = ceil(сума_мг / 10)` (цілочислове ділення з округленням вгору, без `float`). Час (`print_time_s`) уже округлено сервером до хвилини, і він не сумується.
- Рядки йдуть у наявний `costing` `quote`: ціну, розбивку й межі (≤ 32 пластики, ≤ 1 000 000 г на пластик — AC-14) перевіряє сервер так само, як при ручному введенні. Імпорт не може створити рядок, який не пройшов би ручне введення.
- Функцію покривають юніт-тести Vitest на прикладах AC-03 (11,543 г → 11,55 г; 2,001 + 2,001 → 4,01 г) і AC-10.

## Consequences

**Positive**
- Без додаткового запиту на кожну зміну вибору пластику; реакція екрана миттєва, а `quote` іде вже наявним шляхом (дебаунс 200 мс етапу 1).
- Правило «сума → округлення» — одна функція з цілих чисел, і тестується ізольовано.

**Negative**
- Одне доменне правило (сумування з округленням вгору) живе у вебі, а не в Python — це свідомий виняток із духу cost-calculator ADR 0002, тож розходження з бекендом треба ловити тестами на тих самих прикладах.
- Якщо слайсер колись запише понад 3 знаки, сума округлених вгору мг може вийти на 0,01 г більшою за округлену точну суму — лише вгору, тож мінімальний донат не стає меншим (прийнята похибка, §11).

**Neutral**
- Серверний варіант 2 не дав би справжньої гарантії: сервер без стану однаково довіряв би філаментам, які повернув браузер, бо файл уже відкинуто.
