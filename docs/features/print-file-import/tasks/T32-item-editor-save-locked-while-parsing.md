# T32 — «Зберегти зміни» на /item заблоковане, поки парситься файл

## Why

Re-review r7, R14. T31 заблокувала «Підтвердити» в панелі імпорту, але на `/item` є друге
збереження: «Зберегти зміни» в `ItemEditor`. Воно не враховує `importing`
(`ItemEditor.tsx:66`). Якщо парсинг стартував до «Змінити» і завершується під час PUT, `importFile`
викликає `setEditing(false)` (`ItemPage.tsx:41`), `ItemEditor` розмонтовується, а колбеки
`update.mutate` (`ItemEditor.tsx:34-36`) губляться. Probe-тест r7: парсинг на паузі → «Змінити» →
перейменувати на «Органайзер» → «Зберегти зміни» (PUT на паузі, 409 `catalog.name_taken`) → release
парсингу → з'являється панель імпорту, а «Виріб з такою назвою вже є в каталозі» не показано.
Користувач натиснув «Зберегти», не бачить помилки, і правки зникли. Це той самий клас, що R12, і
DoD T31 («поки парсинг у польоті, збереження недоступне на обох сторінках») його покриває.
Джерело: [review 2026-11-11 r7](../_review/review-2026-11-11-r7.md).

## What

- `ItemPage` передає `importing` в `ItemEditor` (або `ItemEditor` сам читає
  `useIsParsingSlicerFile()`); submit-кнопка disabled, а `submit` нічого не надсилає, поки воно true.
- Тест у `ItemPage.test.tsx`: парсинг на паузі → «Змінити» → перейменувати → «Зберегти зміни»
  недоступна; після release парсингу показано панель імпорту (поведінка AC-05 без змін).
